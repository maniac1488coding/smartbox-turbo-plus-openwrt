# Beeline SmartBox TURBO+ — как убрать самопроизвольный откат на стоковую прошивку

**Коротко.** Роутер периодически сам уходил на заводскую прошивку Beeline, после чего
требовалась повторная прошивка и настройка. Причина — счётчик неудачных загрузок
OEM-загрузчика Sercomm: после трёх загрузок, не дошедших до конца, он переключает флаг
загрузки на второй слот, где лежит сток. Решение: сброс счётчика перенесён в самое начало
загрузки, а во второй слот записан OpenWrt — теперь откат невозможен в принципе.

<sub>**English.** A Beeline SmartBox TURBO+ (Sercomm S3 CQR, MT7621) running OpenWrt kept
randomly reverting to the stock ISP firmware. Root cause: the Sercomm bootloader's
failed-boot counter — after three incomplete boots it flips the boot flag to the second
slot holding stock. Fix: the counter reset is moved to the very start of userspace, and
OpenWrt is written into the second boot slot, so the fallback can no longer happen.</sub>

---

**Устройство:** Beeline SmartBox TURBO+ (OEM Sercomm S3 CQR), `beeline,smartbox-turbo-plus`
**Прошивка:** OpenWrt 23.05.6 (r24232-539228933c), ядро 5.15.189, ramips/mt7621
**Адрес роутера:** `192.168.1.1`. В примерах сетевой интерфейс ПК — `enp5s0`.

## Итог одной строкой

**Роутер больше не может уйти на стоковую прошивку: в обоих слотах загрузки теперь OpenWrt.**
Дополнительно сброс счётчика неудачных загрузок перенесён с конца загрузки в её начало.
Проверено на живом устройстве, все настройки и пакеты на месте.

## Быстрый старт

Материалы рассчитаны на конкретное устройство — Beeline SmartBox TURBO+ (OEM Sercomm S3 CQR)
с OpenWrt 23.05.6. Роутер подключён сетевым кабелем к ПК, скрипты запускаются на ПК.

```bash
./discover.sh              # найти роутер на сетевом порту (по умолчанию enp5s0)
./rsh.sh 'uname -a'        # короткий SSH-доступ к роутеру
./sync-slot1.sh            # записать / обновить второй слот прошивки
./restore-backup.sh list   # что есть в бэкапе разделов
```

Перед запуском скриптов, которым нужны device-specific значения, скопируйте
`device.local.example` в `device.local` и подставьте MAC и серийный номер со своей наклейки
(этот файл в `.gitignore`). Подробный разбор причины и всех проверок — в разделах 1–3.

---

## 1. Почему он «сам сбрасывался»

Это не глюк и не «слетающая прошивка». В роутере **два независимых слота прошивки**,
и OEM-загрузчик Sercomm сам переключается между ними:

| Раздел | Адрес | Было | Стало |
|---|---|---|---|
| `mtd3` «Boot Flag» | 0x300000 | байт 7 = `Sercomm0`/`Sercomm1`, **счётчики загрузок** | то же |
| `mtd4` kernel | 0x400000 | **слот 0 — OpenWrt** | OpenWrt |
| `mtd5` Kernel 2 | 0xa00000 | **слот 1 — сток Beeline** | **OpenWrt** |
| `mtd7` File System 2 | 0x3000000 | стоковый rootfs | не используется |

Загрузчик на **каждой** загрузке увеличивал счётчик попыток и переставлял флаг на другой слот,
если система не успевала «подтвердить» удачную загрузку. Три таких загрузки подряд — и роутер
уходил на сток. Дословно из OEM-лога загрузчика:

```
Boot Flag : Sercomm0
...
boot_count1 is FF
write 1 to boot_count1
ranand_erase: start:320000, len:20000
```

Причина «хаотичности»: штатный скрипт OpenWrt `/etc/init.d/bootcount` сбрасывает счётчик
с **`START=99`**, то есть на ~25-й секунде, в самом конце загрузки. Любая просадка питания
до этого момента оставляла счётчик «заряженным». При нестабильном питании он набирал три
страйка быстро.

## 2. Что сделано

### 2.1. Ранний сброс счётчика загрузок

Добавлен `/etc/init.d/bootcount_early` (исходник — `bootcount_early.sh`):

* сброс на **`S00`** — первом шаге rcS (13-я секунда) вместо `S99` (~25-я);
* **безусловная** запись `0xff` (штатный пишет только если там не `0xff`);
* дублирование на штатном выключении (`STOP=99`);
* ведёт историю в `/root/bootcount-history.log` — видно, что записал загрузчик.

Штатный `/etc/init.d/bootcount` не тронут и остаётся дублирующей страховкой.

### 2.2. Второй слот переведён на OpenWrt — откат на сток стал невозможен

Это главное. Штатно OpenWrt помечает разделы второго слота (`mtd5`, `mtd7`) как **read-only**
в device tree, поэтому из OpenWrt туда писать нельзя. Порядок действий был такой:

1. Собран официальный модуль ядра **`kmod-mtd-rw`** (ветка `openwrt-23.05`) через
   **OpenWrt SDK** для ramips/mt7621 версии 23.05.6.
2. Модуль загружен на роутер: `insmod mtd-rw.ko i_want_a_brick=1` — флаг `MTD_WRITEABLE`
   снялся с `mtd0/1/2/5/7`, `mtd5` стал доступен на запись.
3. Во второй слот записано **ядро OpenWrt** с корректным заголовком Sercomm.

Заголовок собран строго по официальному формату OpenWrt
([`scripts/sercomm-kernel-header.py`](https://github.com/openwrt/openwrt/blob/master/scripts/sercomm-kernel-header.py))
и проверен: генератор **байт-в-байт воспроизводит рабочий заголовок нулевого слота**.
Для второго слота изменены только адреса:

```
kernel_offset = 0x00a00100     rootfs_offset = 0x03000000
```

**Почему это работает.** Ядро OpenWrt находит свой rootfs **не по слоту**, а по абсолютным
адресам из device tree: в командной строке нет `root=`, а UBI цепляется к `mtd10`
(конкатенация `mtd6+mtd8+mtd9`). Поэтому то же самое ядро, загруженное со второго слота,
монтирует **тот же самый OpenWrt** с теми же настройками.

**Проверка на живом устройстве:** Boot Flag переключён в `Sercomm1`, роутер перезагружен —
поднялся OpenWrt 23.05.6, командная строка та же, настройки и 145 пакетов на месте.
Флаг потом возвращён в `Sercomm0`.

**Что это даёт.** Загрузчик может переставлять флаг сколько угодно — с любой стороны
загрузится OpenWrt. Стоковой прошивки в загрузочном виде больше нет.
От стока осталась только корневая ФС в `mtd7`; она ничем не используется, ядро OpenWrt
на неё не ссылается, а её собственное ядро затёрто — загрузиться с неё невозможно.

**Приятный побочный эффект:** если ядро в одном слоте когда-нибудь повредится, загрузчик
переключится на другой — и там тоже OpenWrt. Получилась настоящая резервная копия прошивки.

### 2.3. Побочная находка: счётчиков два

Загрузчик ведёт **отдельный счётчик на каждый слот**: для `Sercomm0` он пишет в
`mtd3+0x20001`, для `Sercomm1` — в `mtd3+0x20002`. Это видно в истории:

```
слот 0:  00020000  ff 01 ff ff ...      <- счётчик в 0x20001
слот 1:  00020000  ff ff 01 ff ...      <- счётчик в 0x20002
```

Штатный скрипт OpenWrt чистит только `0x20001`. Наш `bootcount_early` пишет **8 байт**
начиная с `0x20000`, то есть покрывает оба счётчика — сброс работает независимо от того,
какой слот активен.

## 3. Как проверялось

| Что | Результат |
|---|---|
| 6 перезагрузок подряд со сбросом счётчика | Boot Flag неизменно `Sercomm0`, счётчик чист |
| Хук в `/lib/preinit/` из оверлея | **не работает** (сорсится до монтирования оверлея) — `S00` и есть минимум |
| Запись в `mtd5` до модуля | отклоняется ядром (`Operation not permitted`) |
| Запись в `mtd5` после `mtd-rw` | `flags=0x400`, запись проходит |
| Заголовок для слота 1 | воспроизводит заголовок слота 0 байт-в-байт |
| md5 записанного в `mtd5` | `c74cb7a4acb6ed8707cfcbda0aa56716` — совпал |
| **Загрузка со слота 1** | **OpenWrt 23.05.6, настройки целы** |
| Настройки после всех операций | LAN IP `192.168.1.1`, 145 пакетов |

## 4. Обслуживание

### После обновления прошивки

`sysupgrade` обновляет **только нулевой слот**. Второй останется со старым ядром; отката
на сток это не вернёт, но версии разъедутся. После каждого обновления запускайте на ПК:

```bash
./sync-slot1.sh        # запускать из каталога репозитория
```

Скрипт сам считает ядро из нулевого слота, пересоберёт заголовок, загрузит модуль,
запишет второй слот и проверит md5. Проверено — работает.

> **Важно:** если обновление меняет версию ядра (например, `5.15.189` → другая), то
> имеющийся `mtd-rw.ko` перестанет загружаться — модуль привязан к версии ядра.
> В этом случае нужно пересобрать его под новое ядро: скачать соответствующий
> [OpenWrt SDK](https://downloads.openwrt.org/releases/) для `ramips/mt7621` и собрать
> пакет `kernel/mtd-rw` из ветки `openwrt-23.05`
> ([openwrt/packages](https://github.com/openwrt/packages/tree/openwrt-23.05/kernel/mtd-rw)),
> как это сделано в `build/`.
>
> **На защиту от стока это не влияет:** второй слот остаётся с ядром OpenWrt, просто
> старой версии. Роутер в любом случае загрузит OpenWrt, а не стоковую Beeline.
> Синхронизация нужна лишь для того, чтобы версии ядер в слотах совпадали.

### Если захотите вернуть стоковую прошивку

Обратимо: в `backup/mtd5.bin` лежит оригинальное стоковое ядро.

```bash
cd <каталог репозитория>
./rsh.sh 'cat > /tmp/mtd-rw.ko' < tools/mtd-rw/mtd-rw.ko
./rsh.sh 'insmod /tmp/mtd-rw.ko i_want_a_brick=1'
./rsh.sh 'cat > /tmp/mtd5.bin' < backup/mtd5.bin
./rsh.sh 'mtd write /tmp/mtd5.bin /dev/mtd5'
./rsh.sh 'printf 1 | dd bs=1 seek=7 count=1 of=/dev/mtdblock3'   # флаг -> Sercomm1
./rsh.sh 'reboot'
```

### Если сбросите настройки к заводским

Скрипт `bootcount_early` пропадёт (он в оверлее). Второй слот при этом **не пострадает**.
Поставьте фикс заново:

```bash
scp bootcount_early.sh root@192.168.1.1:/etc/init.d/bootcount_early
ssh root@192.168.1.1 'chmod 755 /etc/init.d/bootcount_early; /etc/init.d/bootcount_early enable'
```

## 5. Рекомендации

**Питание.** Нестабильное питание — исходный триггер. Даже с двумя слотами OpenWrt просадки
вредны: каждый обрыв питания во время записи в flash может повредить данные. Замените блок
питания 12 В (у этих коробок типовые проблемы с конденсаторами) или поставьте роутер на UPS.

**Пароль root.** На роутере **не задан пароль root**, а SSH открыт на LAN. Обязательно задайте:

```bash
ssh root@192.168.1.1 'passwd'
```

либо в LuCI: Система → Администрирование.

## 6. Бэкапы

Полный дамп всех 11 разделов NAND (207 МБ) — в `backup/`, снят с рабочего роутера
**до** всех изменений. Восстановление любого раздела:

```bash
./restore-backup.sh list              # что есть
./restore-backup.sh show 5            # сравнить с текущим состоянием
./restore-backup.sh restore 5 --yes   # записать (не отключать питание!)
```

Ключевые разделы: `mtd0` — загрузчик, `mtd1` — карта разделов, `mtd2` — Factory (MAC/EEPROM),
`mtd3` — Boot Flag, `mtd4`/`mtd6` — OpenWrt, **`mtd5` — оригинальное стоковое ядро**,
`mtd8`/`mtd9` — оверлей OpenWrt.

(1 ГБ, скачивается заново); `slot1_openwrt_kernel.bin` — собирается скриптом;
`device.local` — MAC и серийник конкретного роутера.
